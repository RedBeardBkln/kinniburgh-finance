## IMPORTANT discrepancy: tags have no "archived" and no "entity"

The request says the tag list must be scoped to the suggestion's entity and exclude archived tags, and that the server must reject a tag that is archived or not valid for the entity. In this schema that is not expressible: `model Tag` has only `id, name (unique full path), shortName, parentId, createdAt, updatedAt` (no `archivedAt`, no `entityId`). Tags are household-wide; every page (Budgets, Forecast, Transactions, Tag rules) lists ALL tags, and the ledger keys a tag by `entityId|tagId`, so any tag can be used with any entity. I did NOT invent an entity or archive rule. What is implemented: the list is the same one the Budgets / Forecast pages use (all tags, full-path labels, name order, identical for every entity); the server requires the tag to exist. A test reads `prisma/schema.prisma` and fails if `model Tag` ever gains `archivedAt` / `entityId` / `deletedAt`, so the action's validation has to be extended then. The "tag entity mismatch" and "archived tag" tests could therefore not be written as specified; the unknown-tag and malformed-id tests replace them. If you want a stricter notion (for example only tags that have a Budget row in that entity), say so.
