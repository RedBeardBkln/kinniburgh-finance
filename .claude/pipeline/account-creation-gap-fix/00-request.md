Fix the missing "create new account" gap in both account-connection flows so a genuinely new institution/account can be added — not just mapped onto something pre-seeded.

CONTEXT (already root-caused by the orchestrator this session — verify current code state but trust this diagnosis, don't re-derive it from scratch):

The owner (Eric) tried to add a new "CorePlus Credit Union" personal loan account (a $350/mo reimbursement-funded loan for a home bathroom renovation) two ways, and both failed silently:

2. **Plaid "Connect Bank" flow** (`app/accounts/connect/connect-client.tsx`, 3-step link/map/done UI → `app/api/plaid/exchange/route.ts` → `app/api/plaid/confirm-mapping/route.ts`): this actually DID succeed at the Plaid level — a real `PlaidItem` row exists (`itemId` `av4wRqKKpEIBoEEndk43uRzEnzxP18tj5g7Zg`, `institutionName` "CorePlus Credit Union", `institutionId` `ins_124682`, `status: "active"`, a sync already ran once). But `exchange/route.ts` builds its account-mapping `suggestions` by matching Plaid accounts to EXISTING `Account` rows by mask ONLY (`match?.id ?? null`), and the mapping UI's per-account `<select>` only offers `seededAccounts.map(...)` plus `"(skip this account)"` — confirmed no "create new account" option exists in either the UI or `confirm-mapping/route.ts` (which only ever calls `db.account.update()`, never `.create()`). Since CorePlus has no pre-existing Account to match against, it silently has nothing to map onto and never gets created, despite Plaid reporting success. **This PlaidItem is currently real, active, and orphaned (zero Account rows reference it) in production — the fix needs to let the owner resume/complete mapping for this existing item, not just handle it for a brand-new Link flow.**
