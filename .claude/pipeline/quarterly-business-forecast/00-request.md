GROUND-RULE-CRITICAL SCOPE DECISION — already made, do not relitigate, just follow it: this task builds a **percentage-based tax RESERVE estimate**, not a real IRS-bracket-computed tax liability. Reasons, stated plainly so you don't second-guess this: (1) CLAUDE.md ground rule 1 forbids fabricating financial figures — exact federal/state bracket thresholds, the Social Security wage base, and self-employment tax caps are precise, year-specific IRS figures this codebase has no verified source of truth for, and guessing them from training data risks being subtly wrong with real financial consequences; (2) a household's true marginal tax rate depends on their FULL return (filing status, all income sources, deductions) which a single business entity's quarterly view cannot see; (3) ground rule 8 requires this to be observational/draft, never advice-grade precision. So: project net income (real, from real transactions — no fabrication risk there), then multiply by a **user-configurable reserve percentage** (a sensible default like 30%, stored somewhere reasonable — check if there's an existing `AppSetting` or entity-level settings mechanism in the schema/actions to store this rather than inventing a new one) to produce a "set aside approximately $X for taxes this quarter" figure, with UI copy that explicitly says this is a rough cash-reserve estimate for planning purposes, not a computed tax liability, and to confirm the actual rate with a CPA. Do NOT implement Form 1040-ES bracket math, self-employment tax computation, or safe-harbor comparisons — flag those as explicitly out of scope for a future task if you think they'd be valuable, don't build them now.
