Task slug: accrual-draw-dates

Let owners of accrued, usage-based bills (heating oil, firewood) enter estimated draw dates+amounts so the Personal forecast anticipates the expense hitting the account on realistic dates instead of spreading it evenly every month.

CONTEXT (already investigated by the orchestrator this session — verify current code state but trust this diagnosis, don't re-derive it from scratch):

**The problem, confirmed live in code:** `lib/forecast.ts#generateBillOccurrences()` (lines ~301-328) handles a `ScheduledBill` with `amountType: "accrued"` by projecting `annualBudget/12` as an outflow on `autopayDay` (defaults to day 1) EVERY SINGLE MONTH. For McCarthy Heating & Oil ($4000/yr) and Firewood ($1000/yr) — both seeded with `autopayDay: null` per `prisma/seed.ts` comment "No fixed autopay day; bills arrive during heating season" — this means the forecast currently shows a flat ~$333/mo and ~$83/mo outflow in July and August too, when in reality nothing gets charged then; the real hit is a lump sum (or a couple of lump sums) during the actual oil-delivery/firewood-purchase window. The owner (Eric) wants to enter his own estimated date(s) + amount(s) for when these lumps will actually hit, so the forecast reflects reality instead of a flat spread.

**A related model already exists but is NOT wired into the forecast at all:** `AccrualEnvelope` (`prisma/schema.prisma` ~line 325) has `targetAnnualAmount`, `currentBalance`, and `expectedDrawMonths: Json` (e.g. `[10,11,12,1,2,3]` for oil) — already seeded for both "McCarthy Oil" and "Firewood" (`prisma/seed.ts` ~line 498-512). It's displayed today on the Envelopes page (`app/envelope/page.tsx` ~line 394-463, under "Accrual Envelopes" — funded/target progress bar, draw-months list, a manual "Update balance" form) and used for pace-tracking in `lib/notifications.ts` and `lib/monthly-review-build.ts` (accrual-behind-pace warnings). Grepped confirmed: `lib/forecast.ts` never references `AccrualEnvelope` at all — the balance projector and the accrual-tracking system are two completely disconnected halves today.

**No FK links `ScheduledBill` to `AccrualEnvelope` today** — they're independent rows that happen to describe the same real-world thing on the same account, matched only by a human reading the name (`ScheduledBill.payee` = "McCarthy Heating & Oil" vs `AccrualEnvelope.name` = "McCarthy Oil" — not even an exact string match). `ScheduledBill` schema (`prisma/schema.prisma` ~line 263): `{ id, accountId, entityId, payee, amountType (static|fluctuating|accrued), expectedAmount?, autopayDay?, annualBudget?, active, budgetTagId?, budgetEntityId?, @@unique([budgetTagId, budgetEntityId]) }`. `AccrualEnvelope` schema: `{ id, accountId, name, targetAnnualAmount, fundingTransferId?, currentBalance, expectedDrawMonths (Json), createdAt, updatedAt }`.
